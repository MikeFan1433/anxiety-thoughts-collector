## Frozen decisions (for design)

- Who: 第一用户 = 敏感、多疑、日程紧凑、缺少倾诉对象的年轻知识工作者（提出者本人）。群体「20–40 焦虑职场人」仅作延后 ICP，未验证。
- Sharp problem: 焦虑念头出现后无法强制完成「是否值得焦虑」的判断与有上限的应对设计，因而陷入对不确定后果的恐惧；同时在新一轮焦虑时无法立刻调用自己曾经熬过来的证据。
- Slice type: **SLC**
- Aha loop (steps): 打开 → 判断「当下能否逐步推进」（否=内耗成功停手并留轻量记录）→ 是则写契机与念头 → 脑补恐惧+概率 → 影响范围 → 强制 Plan A/B/C → 不可控变量 → Review 红叉不可控 → 确认保存并生成空 outcome → 可打开过关清单
- Non-goals: 诊疗/诊断/危机干预；AI 分析；多用户账号与云协同；原生商店发布；市场推广与付费；心情像素图与游戏化宠物

## 背景

产品工作名：**Anxiety Thoughts Collector（焦虑念头收集器）**。

目标：给经常被杂念拖住的人一个一站式空间，记录、聚焦、冷静拆解并管理焦虑念头，从而减少终日忧虑、无法放松和无法正常享受生活的状态。

本轮约束（提出者已确认）：

- 第一用户是自己，用 2–4 周真实使用验证，再考虑给同类人。
- 核心机制：**先判断能否逐步推进，再填表；Plan A/B/C 就是三套当下思路（强制三套、禁止第四套）；不可控变量在 Review 上打红叉；过关清单独立三拍记录。**
- 暂不考虑推广与商业化。
- 平台：可添加到主屏幕的移动 Web / PWA。

## 用户分析 (5-dimension)

**5-dimension verdict: COMPLETE（第一用户）| DRAFT（群体）**

### Role

高强度认知工作中的个人贡献者/专业人士；对绩效、申请、他人评价等结果没有单方面控制权；工作日与夜晚都可能被念头打断。

### Persona

敏感、倾向于灾难化与过度准备；重视把事情「想清楚」；日程挤，缺少稳定倾诉对象。愿意写字，但只在结构足够短、且能减少失控感时。  
**Anti-persona：** 只要表情心情打卡或冥想的人；已经能稳定填完 CBT 长表的人；需要紧急临床处置的人。

### Objectives

- 本季：减少念头对睡眠与当日决策的劫持。
- 本季：在焦虑出现时有一个强制停手或封顶预案的出口。
- 本年：积累「我曾经这样担心过、后来如何熬过来」的可检索证据。

### Sharp Problems

- 「念头一来就演最坏剧本，停不下来，也分不清是不是真问题」——每日级，强度高。
- 「没有地方强制我写完应对，所以同一类焦虑会反复出现。」
- 「焦虑时想不起自己曾经搞砸过、被拒绝过、然后熬过来了。」

### JTBD + Workflow

- **JTBD:** 当焦虑念头在工位或夜里冒出来，我要先判定该不该继续焦虑；若该推进，就把恐惧、范围和最多三套预案写死，并看见不可控因素被划掉；若只是吓自己，就停手。之后能回填真实结果，也能打开过关证据。
- **Target workflow:** 见下方用户旅程。
- **Preceding workflow:** 触发 → 身体紧张 / 脑内预演。
- **Succeeding workflow:** 执行 Plan A（或 B/C）；或放下内耗；日后回填 outcome（相对当时担心：更差 / 相近 / 更好）；必要时手动另写一条胜利经历。

## 用户旅程（Frozen）

### 旅程 A — 焦虑念头记录

1. 念头出现，打开产品，点「记下念头」。
2. **先判断：** 这是当下可以逐步推进的问题吗？（不是「今晚必须彻底解决」。）
   - **否（成功路径）：** 结束。文案：「这些都是我自己吓唬自己。」仍保存一条轻量内耗记录（时间戳；可选一句）。判断事后可改为「其实能推进」并补全表单。
   - **是：** 继续。
3. 用 1–2 句写：引发焦虑的契机 + 念头本身。
4. 记录当下脑补的恐惧（担心的最坏结果），每条附概率 0–100%。**第 1 条必填；最多 5 条。**
5. 选择焦虑 **影响范围**（高 / 中 / 低）：只影响今晚情绪 / 影响本周工作 / 影响身份或长期后果。不要做成第二套强度滑杆。
6. **强制写下恰好 3 个当下可行思路（禁止第 4 套）：**
   - Plan A：最优方案
   - Plan B：出小差错时的平替（提示：如果 A 出现小状况，仍可以做的退一步方案是什么？）
   - Plan C：最坏结果出现后的心理与规则准备——搞砸了，大不了怎么办
7. 列出当前无法控制的变量。
8. 进入 **Review（aha 屏，不是第二张长表）：** 系统把不可控变量打红叉，视觉告知不用扛这些；摘要展示恐惧、范围、A/B/C。
9. 确认后保存。系统自动生成空的 **outcome** 字段，结果出来后再填。
10. 列表藏在首页「已有念头」按钮之后。打开任意念头可修改任何字段；outcome = 结果叙述 + 相对**当时担心的最坏结果**：比担心的更糟 / 和担心的差不多 / 比担心的更好。禁止使用「是否达到预期」（语义会翻车）。
11. 已有结果的念头可选择「记录到过关清单」：把念头、预案与结果收入过关清单，之后可查看。已收入则改为查看，不重复生成。

### 旅程 B — 过关清单

1. 点「记录胜利经历」，或从已有结果的念头「记录到过关清单」。
2. 分别填写（或由念头带入）：发生前的焦虑和担忧；中途如何应对、如何熬过来；最后的结果（允许并不完美）。
3. 保存后可随时查看。

## 目标 / 非目标

**目标**

- 内耗路径极短且算成功；能推进路径强制写完 A/B/C 并看见不可控被划掉。
- 念头可回看、可改、可回填相对担心的真实结果。
- 过关清单可独立创建与随时打开。
- 非医疗声明清晰。

**非目标**

- 治疗、诊断、危机干预步骤。
- AI、社交、统计仪表盘、账号体系、付费墙锁核心回路。

## Delivery Slice

**SLC：** 手机上走通旅程 A（含内耗短路 + Review 红叉）与旅程 B；保存后可编辑 outcome。

## 功能需求（仅 in-slice）

1. 首页：记下念头；已有念头（进入列表，不在首页铺开）；过关清单 / 记录胜利经历。
2. 分流题：当下能否逐步推进。否 → 内耗成功页 + 轻量保存。
3. 能推进表单：契机与念头；1（+可选 2）条恐惧及 0–100% 概率；影响范围高/中/低；Plan A/B/C 全必填；不可控变量。
4. Review：红叉不可控 + 摘要 + 确认保存 + 生成空 outcome。
5. 详情/编辑：全部字段可改；outcome 三选一对照「当时担心」；已有结果可「记录到过关清单」。
6. 过关：胜利经历三字段增删改查。
7. 免责：非医疗。
8. 备份：顶栏「备份与恢复」弹出导出 JSON / 导入并替换。
9. 已有念头可按状态筛选：全部 / 推进中 / 内耗 / 已有结果。
10. 首页定位句为蒙田引语（无句号）：「我的一生都充满了不幸，但其中大部分都未发生过」。

## 附录 A — 协议语义（不得改）

- 分流问的是 **当下能否逐步推进**，不是能否彻底解决。
- 不能推进 = 内耗 = 成功停手，仍留痕。
- A/B/C 即全部当下思路，强制三套、禁止更多。
- 不可控变量不是行动项；Review 必须视觉否定它们。
- Outcome 对照的是 **当时担心的最坏结果**，不是「希望有没有实现」。

## 附录 B — SLC / Aha / Scope

- SLC；候选 aha = 内耗停手，或 Review 上看见不可控被红叉且三套预案已封顶。
- 过关清单 Required 最小三字段。
