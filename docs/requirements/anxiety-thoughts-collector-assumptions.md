# Anxiety Thoughts Collector — 八类假设（identify-assumptions-new）

**Date:** 2026-08-14  
**范围:** 个人优先 SLC；暂不 GTM。置信度按「当前证据」而非愿望。

从三个视角先看失败模式：

- **PM：** 市场已有 Worry Watch；用户可能并不需要新 App，只需要一张检查清单。
- **Designer：** 焦虑峰值时认知带宽极低；字段一多就会弃用；过关清单若像「成功学」会反感。
- **Engineer：** 过早上云/账号/原生壳会把个人工具做成半成品平台。

| 类别 | 假设 | 置信 | 如何测 |
|---|---|---|---|
| Value | 走完协议比继续反刍更让人愿意采用 | 中 | H2：协议前后 0–10 |
| Value | 过关清单在新焦虑时提供勇气而非比较伤害 | 低 | H3：打开次数 + 用后一句 |
| Usability | 能解决路径的字段仍能在 5–10 分钟内填完 | 中 | H1：从念头出现到保存的时长 |
| Usability | 「内耗停手」会被体验为解脱而非被否定 | 低 | 内耗条目占比与是否后悔标记 |
| Viability | 个人 impact 足以证明值得维护代码 | 中 | H4：2–4 周留存 |
| Viability | 暂不收费不影响本轮成功定义 | 高 | 本轮成功 = 使用而非收入 |
| Feasibility | PWA 添加到主屏幕足够「像 App」 | 中 | 你是否从主屏幕打开（vs 浏览器书签） |
| Ethics | 免责声明足以避免「这是治疗」的误解 | 中 | 文案评审；不提供危机步骤 |
| Ethics | 反复记录灾难剧本不会强化焦虑 | 低 | 若 H2 连续为假则停更功能、减字段 |
| GTM | 本轮不需要获客 | 高 | 显式非目标 |
| Strategy | 停手+封顶+过关 是可防守的交叉格 | 低 | 对照 Worry Watch 用 2 周 |
| Team | 单人 vibecoding 能维持 SLC 质量 | 中 | slice 是否在一周内可自用 |
