# Anxiety Thoughts Collector — Sharp Problem Test

**Date:** 2026-08-14  
**Skill:** sharp-problem-test（Building Rocketships Ch.1）  
**Confidence:** 中（第一用户自述；竞品为公开产品信息；无付费/切换成本实测）

## Sharpness Verdict: NEEDS MORE EVIDENCE

问题对第一用户足够痛、足够频；作为**可扩展数字产品/公司定义问题**尚未过 ≥3x 与「目的型替代品是否已做完同一 job」两道关。允许写个人 SLC PRD，整体判断封顶为 `PROCEED_WITH_EYES_OPEN`。

---

### Question 1: Alternatives

第一用户今天很可能：在脑子里循环、偶发写进备忘录、问 ChatGPT、或什么都不做直到失眠。这些都是 duct-tape。

**不要只接受「没有工具」。** 目的型替代包括：

| 替代 | 完成的 job | 与本想法的差距 |
|---|---|---|
| 什么都不做 / 反刍 | 零摩擦，代价是睡眠与决策 | 无拆解、无停手、无证据 |
| 备忘录 / Notion | 能写，不能强制协议 | 用户可跳过判断与封顶 |
| 通用 LLM | 能对话拆解 | 无结构化档案、无过关清单、无封顶规则；且焦虑当下不一定愿意「打开聊天」 |
| Worry Watch | 引导式焦虑日记 + 结果是否如担心的糟 | 缺硬分流「现在不能解决=内耗停手」；缺 A/B/C 封顶；缺人生级过关清单 |
| WorryTree | CBT 担忧树（现实 vs 假设担忧） | 更偏临床分流，弱于三预案封顶与过关勇气 |
| Clarity / Moodnotes / Thought Diary | CBT 思维记录 | 表格长，职场即时捕获弱；无过关清单 |
| Daylio / Finch | 心情与习惯 | **不是同一 job** |

Harness 规则：不因「可以贴进 ChatGPT」单独判 NOT SHARP。若**目的型产品已做完同一 hired job** → NOT SHARP。

Worry Watch 已完成「记下担忧、分析、行动、对照结果」的大部分。本想法的增量是 **停手规则 + 三套封顶 + 过关清单**。增量是否构成新的 sharp problem，**证据不足**——不能判 SHARP，也不因「市场已有日记」直接判 NOT SHARP（那会误杀个人协议产品）。

### Question 2: Prevalence

- **Market size:** 焦虑在年轻职场人群中普遍（定性；NEEDS RESEARCH 精确 TAM，本轮不编造人数）。个人工具不依赖 TAM 才能开工。
- **Problem growth:** 信息过载、绩效不确定、LLM 既增加「随时倾诉」也增加比较焦虑。问题未在消失。同时心理健康 App 与聊天机器人正在**部分吸收**同一需求。
- **Niche-ness:** 不是全人类；是「灾难化 + 缺少倾诉 + 需要强制结构」的知识工作者。过窄则难规模化，过宽则变心情日记。
- **Frequency:** 对第一用户为 **每日多次**。高频支撑个人工具；也要求捕获必须极短，否则会弃用。

### Question 3: Value

本轮明确 **暂不考虑付费与获客**。付费意愿未知。

替代的「花费」：

- 睡眠与决策质量（高，难货币化）
- 现成 App 订阅（常见 freemium，金额未作为本轮决策依据）
- 时间：一次完整拆解约数分钟；若协议过长，焦虑当下会拒绝使用

对个人 SLC，价值代理指标不是 ARR，而是：**会不会在念头出现的 5 分钟内打开，并在走完后循环下降。**

### Improvement bar check（≥3x vs 现状工作流）

| 对照 | 是否可能 ≥3x | 说明 |
|---|---|---|
| vs 纯反刍 | 是（假设成立时） | 从无限循环到一次封顶记录 |
| vs 备忘录 | 可能 | 取决于「强制」是否真的改变行为 |
| vs Worry Watch | **很可能 <3x** | 同一大类 job；这是最大的 sharpness 风险 |

作为公司：未过 3x 关。作为给你自己用的 SLC：对照应是 **你的现状（反刍/碎片笔记）**，而不是「打败 Worry Watch」。

### Recommendation

1. 按个人 SLC 写 PRD 并（在你签字后）实现最小回路。
2. 2–4 周只测 H1–H4（见 PRD），不要同时做 AI/多用户/商店发布。
3. 若 H1 或 H4 失败：数字化可能不是缺口，协议本身用纸也能做。
4. 在 H1–H4 为真之前，**不要**把该想法当成可融资或可推广产品。

### Analogous case from the book

Calendly 的 sharp problem 是「跨组织约时间，邮件来回经常失败」——替代品差且代价高。对照：Calendly **拒绝**「在 App 里发邮件分享链接」，因为复制粘贴已经够用。

本想法更接近后者风险：市场已有「引导式焦虑日记」。过关清单 + 封顶规则必须被证明是 **新的 hired job**，而不是日历 App 里再做一个「从 App 发邮件」。

## 去风险假设（与 PRD 同步）

| ID | 假设 | 若为假 |
|---|---|---|
| H1 | 念头出现 5 分钟内会打开本工具 | 捕获摩擦仍高于反刍，产品无 aha |
| H2 | 走完协议后主观循环强度下降 | 结构变成新的焦虑作业 |
| H3 | 新念头时会打开过关清单且感到有用 | 过关清单可降为 Helpful / 延后 |
| H4 | 2–4 周后仍用本工具而非备忘录/Worry Watch | 不应扩展范围；考虑停在协议文档 |
